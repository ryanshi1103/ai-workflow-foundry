# GitHub Pin Recommendations

Pins should tell one engineering story and must be applied manually only after
the relevant branches are pushed and their public CI/status is verified.

## Recommended public pins

1. **`ai-workflow-foundry`** — flagship local-first AI workflow and agent
   engineering platform.
2. **`feedback-intelligence-system`** — use the existing
   `feedback-analysis-system` repository after the approved in-place rename; it
   demonstrates a complete AI-assisted data/review/export application.
3. **`confera-media-skills`** — reusable capability contracts and bounded media
   workflow design.
4. **`print-ready-nameplate-generator`** — deterministic application automation
   and real output validation.
5. **`oppo-photo-archive`** — local-first transactional safety and recoverable
   device automation.
6. **`oppo-phone-control`** or one polished systems project — optional breadth;
   omit this pin if a tighter AI-only portfolio is preferred.

## Important visibility constraints

- The `ryanshi1103` profile repository renders the portfolio README; it does not
  need to consume a product pin.
- Huiying / MediaFlow is private and should not be represented by a fake public
  repository. Its sanitized architecture and contract live inside FlowFoundry,
  and the profile links to that public evidence.
- `ai-workspace-manager` is a transitional mirror. Avoid pinning it beside
  FlowFoundry unless it remains an intentionally independent install target.
- Off-thesis projects can remain public without occupying headline pins.

## Manual verification before pinning

- public default branch contains the reviewed commits;
- Actions/tests are green and badges resolve;
- README claims match reproducible behavior;
- license and privacy boundary are clear;
- links use the final repository names;
- no private media, personal data, credentials, or production configuration is
  present.
